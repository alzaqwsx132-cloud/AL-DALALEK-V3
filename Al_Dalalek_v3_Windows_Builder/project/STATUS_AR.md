# نظام الدلالك — تقرير التحديث الثالث (2026-11-05)

## تعديلات أنجزت في الكود المصدري

1. **تنبيهات المخزون:** اختيار مستودع واحد من إعدادات لوحة التحكم في جهة اليسار؛ تنبيهات ذلك المستودع فقط؛ مقارنة الرصيد مع `reorder_level` لكل صنف؛ إظهار الأصناف ذات الرصيد صفر؛ الاحتفاظ باختيار المستودع محلياً على الجهاز، وليس إعداداً سحابياً.
2. **لوحة التحكم والتقارير:** السند متعدد المواد يُحتسب سنداً واحداً في الإحصاءات والمخططات. التقرير الشهري يعرض عدد السندات حسب النوع، ولا يجمع أعداد وحدات مختلفة. كشف الأقسام أصبح يحسب التحويلات الواردة والصادرة.
3. **بحث شامل:** حقل بحث أعلى التطبيق للبحث عن السند برقمه وفتحه مباشرة؛ البحث عن أسماء الأصناف والمستودعات والأقسام مع الانتقال إلى شاشة القسم المناسب. لا يفتح بطاقة الصنف المحددة تلقائياً.
4. **فتح السند:** المحافظة على المعرف الأصلي، مع تحسين تجميع الحركات القديمة حسب النوع والتاريخ والرقم حتى لا تختلط سنوات مختلفة؛ إظهار اسم القسم المستلم عند توفره.
5. **الوحدات:** الإبقاء على الواجهة وإدخال الوحدة المختارة والتحويل بدقة 0.001 في الكود، مع اختبارات حسابية. **ما زال تشغيل التحويل الفعلي في قاعدة البيانات مشروطاً بالترحيل الآمن ومطابقة الدوال الموجودة.**
6. **الطباعة:** إعدادات طباعة داخل نافذة عرض السند: A4 عمودي أو أفقي، إظهار الترويسة والملاحظات العامة، وتنسيق 16 للعناوين و14 للتفاصيل مع ترويسة ملوّنة حسب نوع السند؛ طباعة السند فقط عند فتحه.
7. **البيانات الكبيرة:** جلب السندات والأصناف والمستودعات والأقسام والوحدات بصفحات متتابعة عوض الاقتصار على أول 1000 سجل.
8. **أمان أولي:** عدم تخزين `password_hash` ضمن جلسة المتصفح وإزالة عرض بيانات الدخول الافتراضية من واجهة تسجيل الدخول. **هذا لا يعالج ضعف آلية المصادقة في قاعدة البيانات.**
9. **تشخيص الترقيم:** إضافة `supabase/diagnostics/READ_ONLY_PRECHECK.sql` لفحص بنية الترقيم وأرقام السندات الحالية دون أي تعديل.
10. **حاجز حماية:** وضع حظر `RAISE EXCEPTION` ببداية ترحيل الوحدات الاختياري السابق حتى لا يُشغّل قبل مراجعة الصلاحيات وتوقيع دالة `create_voucher` الحية.

## نتائج الفحص الفعلي

- لم تُجرَ اختبارات اتصال مع Supabase الحي، ولا تنفيذ أو تعديل لأي بيانات في قاعدة البيانات.

## متطلبات لم تكتمل

- **ترقيم الخادم الجديد** المستقل حسب نوع السند والسنة وتخصيص البادئة والبداية؛ يلزم الاطلاع على مخطط `vouchers` ونسخة دالة `create_voucher` الحية حتى لا تتكرر الأرقام أو يتعطل حفظ السندات.
- **إعادة ترقيم السندات القديمة:** المعاينة الموجودة أولية من سجل الحركات؛ قد تحتاج معالجة سندات ملغاة أو مؤرشفة. لا تُنفذ قبل نسخة احتياطية معتمدة، معاينة شاملة، موافقة المستخدم الصريحة. لم يُغيّر أي رقم تاريخي.
- **تعديل السندات المعتمدة:** لا يوجد حتى الآن مسار RPC آمن ثبت أنه يعكس المخزون ويستبدل جميع الأسطر في معاملة واحدة. لا ينبغي إجراء التعديل مباشرة على جدول الحركات.
- **وحدات القياس السحابية:** ترحيل الوحدات المرفق للمراجعة فقط، وممنوع التنفيذ افتراضياً لعدم وجود مصادقة/RLS آمنة في نموذج المشروع الحالي. يلزم إنشاء صلاحيات خادمية أولاً.
- **الأمان:** ترحيلات المشروع الأصلية تمنح `anon` صلاحيات واسعة، وتحتوي على كلمة مرور مدير افتراضية معروفة. يلزم إصلاحها على الخادم، وتغيير كلمة مرور المدير قبل نشر أي تطبيق على الإنترنت.
- **EXE:** المشروع المرفق مصدر React، وليس ملف تشغيل Windows `.exe`. لم يكتمل بناؤه كبرنامج سطح مكتب.

## تشغيل نسخة التطوير (بعد التحقق)

1. انسخ `.env.example` إلى `.env`، وأدخل بيانات مشروع Supabase الحقيقي بعناية (لا تستخدم `service_role` في الواجهة).
2. نفّذ `npm ci` ثم `npm run test:logic` ثم `npm run typecheck` ثم `npm run build`.
3. راجع أخطاء البناء، ثم اختبر CRUD والبيانات التاريخية باستخدام **قاعدة بيانات تجريبية مستقلة ونسخة احتياطية** قبل النشر.
4. فحص الترقيم: تشغيل الاستعلامات `supabase/diagnostics/READ_ONLY_PRECHECK.sql` (استعلامات SELECT فقط)، ثم مراجعة نتائجها مع مطور القاعدة قبل تغيير أي دالة.
